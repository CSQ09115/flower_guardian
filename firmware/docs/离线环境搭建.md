# 护花使者 · ESP32 离线开发环境搭建记录

> 适用场景：国内网络无法访问 PlatformIO 官方下载服务器（dl.registry.platformio.org 返回 403）时，
> 用**乐鑫官方国内镜像**手工组装 ESP32 编译环境。
> 这套方法已在 ESP32-S3-N16R8 + PlatformIO Core 6.2.0 + 平台 espressif32 8.0.0 上验证通过。

---

## 一、问题是怎么被定位出来的（排障方法论）

| 步骤 | 做了什么 | 结论 |
|---|---|---|
| ① | `pio run` 卡在 `Downloading 0%` 超过 1 小时 | 不是慢，是请求没成功 |
| ② | `curl` 直连下载服务器 | 返回 **403 Forbidden**（服务器主动拒绝） |
| ③ | 换浏览器 UA、换 PlatformIO 官方客户端 UA 再试 | 依然 403 → 排除"身份误判" |
| ④ | 换手机热点（出口 IP 完全变了）再试 | 依然 403 → 排除"单条宽带被封" |
| ⑤ | 用阿里/腾讯公共 DNS 对比解析结果 | IP 一致 → **排除 DNS 污染** |
| ⑥ | 测乐鑫国内 CDN（dl.espressif.cn） | **4.3 MB/s** → 找到可用通道 |

**结论**：PlatformIO 的下载 CDN 对中国地区 IP 有拦截策略，换网络、换 DNS、装驱动都无效——
必须**绕过它的下载服务器**，改用乐鑫官方国内镜像拿"原材料"，再手工组装。

> 教学要点：学生遇到"进度条卡住"时，最常见的错误是反复重启软件。
> 正确做法是**每一步都拿证据、排除变量**，而不是猜。

## 二、工具链到底是什么（答辩可能会问）

在 x86 电脑上编译出 ESP32（Xtensa LX7 架构）能跑的机器码，叫**交叉编译**。
我们这套环境实际包含：

| 组件 | 作用 | 来源 |
|---|---|---|
| `toolchain-xtensa-esp-elf` | Xtensa 交叉编译器（ESP32/S3 用） | 乐鑫 crosstool-NG 14.2.0 |
| `toolchain-riscv32-esp` | RISC-V 交叉编译器（S3 的 ULP 协处理器用） | 同上 |
| `framework-arduinoespressif32` | Arduino 核心源码（arduino-esp32 3.3.12） | 乐鑫 arduino-esp32 |
| `framework-arduinoespressif32-esp32s3-libs` | S3 芯片的 ESP-IDF 预编译库 | 乐鑫 arduino-esp32 |
| `tool-esptool` | 烧录工具（把固件写进 Flash） | 乐鑫 esptool 5.4.0 |
| `tool-esp-rom-elfs` | ROM 阶段的 ELF 文件 | 乐鑫 esp-rom-elfs |
| 其余 13 个包 | 调试器/文件系统工具等，Arduino 项目用不到 | 占位空包（见下文） |

## 三、一键复现步骤（换电脑时按此顺序执行）

所有脚本都在 `firmware/tools/` 目录下，依次运行：

```bash
python tools/install_toolchain.py   # 1. 从乐鑫国内镜像下载并解压 6 个真实工具包
python tools/install_extra.py       # 2. 补装 esptool 和 esp-rom-elfs
python tools/fix_piopm.py           # 3. 给手工包补 .piopm "验收单"（关键！）
python tools/make_stubs.py          # 4. 给用不到的包生成占位包，阻止 PIO 联网
python tools/fix_libs.py            # 5. 重构 esp32s3-libs 目录 + 生成芯片构建脚本
python tools/patch_core.py          # 6. 给核心构建脚本补板级宏定义补丁
```

然后：

```bash
pio run          # 编译
pio run -t upload --upload-port COM5   # 烧录（串口号按实际修改）
```

### 关键知识点

1. **`.piopm` 文件**：PlatformIO 判断"这个包装好了没有"的依据是包目录里的 `.piopm` 清单，
   而不是 `package.json`。手工摆进去的目录没有这个文件，PIO 会无视并继续联网下载。
2. **占位包（stub）**：平台配置里声明的包有 20 多个，但 Arduino 项目只需要 6 个。
   给用不到的包造一个"空壳 + 合规身份证"，PIO 就不会去下载它们（省 1GB+ 流量）。
   注意版本号要和 `platform.json` 里的要求一致，否则 PIO 仍会认为"版本不符"而去下载。
3. **国内镜像地址**：乐鑫为中国用户提供了 GitHub 资源镜像，
   格式 `https://dl.espressif.cn/github_assets/<原 GitHub 路径>`，速度 4MB/s 以上。
   索引文件：`package_esp32_index_cn.json`（arduino-esp32 的 release 资产里就有）。

## 四、手工组装导致的 4 处适配补丁（重要，答辩可讲）

因为官方分发包里带的一些"胶水文件"不在乐鑫的原始压缩包中，我们做了 4 处等价替换：

| 补丁 | 位置 | 原因 |
|---|---|---|
| ① `tools/platformio-build.py` 复制 | 框架包 tools 目录 | 乐鑫把 PIO 构建脚本命名为 `pioarduino-build.py`，而 PlatformIO 找的是 `platformio-build.py` |
| ② libs 包路径兼容 | 同上脚本第 40 行 | 脚本原本面向"合并 libs 包"，官方平台 8.0.0 用的是"按芯片分开的包"（`-esp32s3-libs`） |
| ③ `esp32s3/pioarduino-build.py` 自研 | esp32s3-libs 包内 | 官方包里带这个文件用于注入编译参数，乐鑫原始包没有；我们读取包内 `flags/` 下的参数清单等价生成 |
| ④ 板级宏 + 核心头文件路径 | 框架包构建脚本 | 补 `ARDUINO_BOARD`/`ARDUINO_VARIANT` 宏和 `cores/esp32` 头文件搜索路径 |

第 ③ 项补丁的原理：libs 包自带 `flags/` 目录，里面是 IDF 的完整编译参数清单
（`includes` / `defines` / `c_flags` / `cpp_flags` / `ld_flags` / `ld_libs` / `ld_scripts`），
脚本读取这些清单并注入 SCons 构建环境，效果与官方文件等价。

## 六、烧录常见问题

> ⚠️ **本款板子有两个 Type-C 口，必须插对**（这是本次踩到的最大的坑）

| 接口 | 设备管理器里的样子 | 能不能烧录 | 说明 |
|---|---|---|---|
| 原生 USB 口 | `USB\VID_303A&PID_4001` → COM5 | ❌ **不能** | 芯片自带的 USB-OTG，跑固件时用作 USB CDC 日志口；没有 DTR/RTS 复位电路，esptool 连不上（报 `No serial data received`） |
| **标 "COM" 的口**（右侧） | `USB\VID_1A86&PID_55D3` → COM7 | ✅ **能** | 沁恒 **CH343** 串口芯片，DTR/RTS 复位电路齐全，esptool 可自动进下载模式，烧录 18 秒完成 |

**结论：烧录和看串口输出都走 CH343 那个口（COM7）。** 插错口的表现是
`Failed to connect to ESP32-S3: No serial data received`——不是驱动问题，换口即可。

| 现象 | 原因 / 处理 |
|---|---|
| `Could not open COM5, port is busy` | 串口被占用：关闭 PlatformIO 串口监视器、Arduino IDE、厂家刷机工具后重试 |
| 设备管理器里 COM 口是灰的 / `Present: False` | 幽灵设备（板子没插或没上电）：重新插拔，数据线要接板子**右侧标 COM 的口** |
| 一直打印 `Connecting.....` | 手动进下载模式：按住 **BOOT** 键 → 按一下 **RST** 键 → 松开 BOOT |
| 串口有输出但 LED 不闪 | 改 `src/main.cpp` 里的 `LED_PIN`（本工程已确认为 GPIO 48） |
